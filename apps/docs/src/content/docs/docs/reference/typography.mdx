  { sz: "{ text: '9xl' }", tw: "text-9xl" },

  { sz: "{ text: '--spacing(4)' }", tw: "text-[--spacing(4)]" },
]} />

`text: '--spacing(4)'` is a Tailwind **build-time function** (v4.3.2+), not a
CSS variable — a bare `--token` stays parenthesized var sugar (`text-(--size)`)
while a `--name(...)` call becomes a bracketed arbitrary value
(`text-[--spacing(4)]`). This one rule applies to every value position, not just
font-size; see [sz Props → CSS Variables](/docs/sz-props/#css-variables)
for the full contrast. You write no brackets or parens either way.

## Text Shorthand (size + leading merged)

```tsx
// { text, leading } together → merged single class
{ text: 'lg', leading: 7 }    // → text-lg/7
{ text: 'sm', leading: 'tight' } // → text-sm/tight
```

## Content (Pseudo-elements)

<PropTable rows={[
  { sz: "{ content: 'none' }", tw: "content-none" },
  { sz: "{ content: '\"\"' }", tw: "content-['']" },
  { sz: "{ content: \"''\" }", tw: "content-['']" },
  { sz: "{ content: '\"hello\"' }", tw: "content-['hello']" },
  { sz: "{ content: '--c' }", tw: "content-(--c)" },
]} />

:::tip[Quote style]
Both `content: '""'` and `content: "''"` compile to `content-['']` — the compiler normalizes all quoted content values to single-quote brackets (Tailwind convention).
:::

## Examples

```tsx
// Heading
<h1 sz={{
  text: '4xl',
  weight: 'bold',
  tracking: 'tight',
  leading: 'tight',
  color: 'gray-900',
}} />

// Monospace code label
<span sz={{
  fontFamily: 'mono',
  text: 'xs',
  tracking: 'wider',
  textTransform: 'uppercase',
  color: 'blue-600',
  bg: 'blue-50',
  px: 2,
  py: 0.5,
  rounded: 'sm',
}} />

// Truncated description
<p sz={{
  text: 'sm',
  color: 'gray-600',
  lineClamp: 2,
}} />
```
