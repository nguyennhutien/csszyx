The hydration API provides fine-grained control over SSR mismatch detection,
abort protocol, and recovery. Most apps only need `initRuntime()` — the rest
is available for advanced use cases.

## Hydration Lifecycle

<Steps>

1. **`startHydration()`** — begin hydration session

2. **`loadMangleMapFromDOM()`** — read the injected checksum mangle map from the `<script>` tag

3. **`verifyMangleChecksum()`** — validate SHA-256 against `data-sz-checksum`

4. **If invalid** — `abortHydration()` preserves SSR HTML and CSS intact

5. **If valid** — React hydrates normally

6. **`endHydration()`** — close session, emit audit log

</Steps>

:::danger[Non-negotiable]
On checksum mismatch in production, `abortHydration()` is called
automatically. React hydration is blocked. The server-rendered HTML
and CSS remain intact so the user sees a correctly styled page.

This behavior is intentional and cannot be overridden in production builds.
:::

## Core Functions

### `startHydration()`

Opens a hydration session. Call before any validation or React render.

```ts
function startHydration(): void;
```

### `endHydration()`

Closes the current hydration session.

```ts
function endHydration(): void;
```

### `abortHydration()`

Aborts hydration. Blocks React from taking over the DOM.

```ts
function abortHydration(): void;
```

### `isHydrationAborted()`

Returns `true` if `abortHydration()` has been called.

```ts
function isHydrationAborted(): boolean;
```

### `isHydrating()`

Returns `true` if a hydration session is active.

```ts
function isHydrating(): boolean;
```

## Mangle Map Verification

### `loadMangleMapFromDOM()`

Reads the injected checksum mangle map from the `#__CSSZYX_MANGLE_MAP__`
script tag in the DOM. The legacy `#__SZ_MANGLE_MAP__` id is still accepted
for older builds.

```ts
function loadMangleMapFromDOM(): MangleMap | null;

type MangleMap = Record<string, string>; // { 'class:p-4': 'z', 'var:--_sz-p:--cz': '--cz' }
```

When `production.mangleVars` or `production.mangleGlobalVars` emits CSS
variable aliases, the checksum payload includes both class and CSS-variable
entries. One original dynamic variable can map to more than one mangled name,
so one-to-many variable entries are namespaced with the mangled name in the
checksum key. Global aliases use the same `var:` namespace, for example
`var:--brand-primary`.

### `verifyMangleChecksum(expectedChecksum)`

Compares the expected mangle checksum with the checksum embedded on
`<html data-sz-checksum="...">`. Returns `true` if they match.

```ts
function verifyMangleChecksum(expectedChecksum: string): boolean;
```

### `verifyMangleMapIntegrity()`

Validates the injected mangle map against the embedded checksum.

```ts
function verifyMangleMapIntegrity(): boolean;
```

### `validateHydrationClass(mangledClass, map)`

Checks that a single mangled class exists in the mangle map.

```ts
function validateHydrationClass(mangledClass: string, map: MangleMap): boolean;
```

## Error Inspection

### `getHydrationErrors()`

Returns all recorded hydration errors for the current session.

```ts
function getHydrationErrors(): HydrationError[];

interface HydrationError {
  type: HydrationErrorType;
  message: string;
  class?: string; // The mangled class that failed (if applicable)
  timestamp: number;
}
```

### `clearHydrationErrors()`

Clears the error list. Useful for testing.

```ts
function clearHydrationErrors(): void;
```

## Error Types

```ts
type HydrationErrorType =
  | "checksum_mismatch" // SHA-256 does not match
  | "missing_manifest" // No mangle map in DOM
  | "invalid_manifest" // Mangle map is malformed
  | "class_not_found" // Mangled class has no mapping
  | "token_invalid"; // Recovery token signature is invalid
```

## Recovery Tokens

Recovery tokens allow trusted mangle maps to be accepted even when the
main checksum check fails. Available in development only.

### `verifyRecoveryToken(token, map)`

Verifies a recovery token against a mangle map.

```ts
function verifyRecoveryToken(token: string, map: MangleMap): VerificationResult;

interface VerificationResult {
  valid: boolean;
  mode: RecoveryMode;
  expiresAt?: number;
}
```

### `hasRecoveryToken()`

Returns `true` if a recovery token is present in the DOM.

```ts
function hasRecoveryToken(): boolean;
```

### `getRecoveryMode()`

Returns the current recovery mode.

```ts
type RecoveryMode = "none" | "csr" | "dev-only";
function getRecoveryMode(): RecoveryMode;
```

### `enableCSRRecovery()` / `disableCSRRecovery()` / `isCSRRecoveryAllowed()`

Manually enable or disable client-side recovery.

```ts
function enableCSRRecovery(): void;
function disableCSRRecovery(): void;
function isCSRRecoveryAllowed(): boolean;
```

## SSR Context

### `isSSREnvironment()`

Returns `true` when running in an SSR context (no DOM available).

```ts
function isSSREnvironment(): boolean;
```

### `getSSRContext()`

Returns the current SSR context object.

```ts
function getSSRContext(): SSRContext | null;

interface SSRContext {
  buildId: string;
  checksum: string;
  timestamp: number;
  hasRecoveryTokens: boolean;
}
```

## The `window.__csszyx` Runtime Object

Every production-mangled build installs `window.__csszyx`, carrying the mangle
map and its lookup helpers. It is delivered twice, first-wins: an inline script
in the build-emitted HTML, and a generated module inside the JS bundle itself
(vite/rollup lanes) that installs only when the HTML script has not already —
so pages the build does not own, such as a bundle embedded in a host shell or
served under a CSP that strips inline scripts, still receive the map.
`mangleMap` stays class-only, while `varMangleMap` contains CSS variable
mappings when `production.mangleVars` is enabled.

```ts
interface CsszyxRuntimeObject {
  mangleMap: Record<string, string>;
  varMangleMap: Record<string, string | string[]>;
  checksum: string;
  encode(originalClass: string): string | undefined;
  decode(mangledClass: string): string | undefined;
  encodeVar(originalVar: string): string | string[] | undefined;
  decodeVar(mangledVar: string): string[];
  decodeGlobalVar(mangledVar: string): string | undefined;
  decodeAll(el: { className: string }): string[];
}
```

The runtime helpers (`szr`, `szcn`, `szDecode`) read this object for their
mangle-aware paths; when it is absent they fall back to identity behavior. For
application code, prefer the typed wrappers from `@csszyx/runtime` over
touching `window.__csszyx` directly.

## Example: Manual Hydration Guard

For advanced control over the hydration process:

```tsx
import {
  startHydration,
  endHydration,
  abortHydration,
  loadMangleMapFromDOM,
  verifyMangleChecksum,
  isHydrationAborted,
} from "@csszyx/runtime";

// In your app entry before React.hydrate()
startHydration();

const mangleMap = loadMangleMapFromDOM();
const checksum = document.documentElement.dataset.szChecksum;

if (!mangleMap || !checksum || !verifyMangleChecksum(checksum)) {
  abortHydration();
}

if (!isHydrationAborted()) {
  // Safe to hydrate
  hydrateRoot(document.getElementById("root"), <App />);
}

endHydration();
```
