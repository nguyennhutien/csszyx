CSSzyx resolves style variables **at build time** — the same way it resolves inline
objects. No runtime overhead, no `className="[object Object]"`.

## Direct Reference

The simplest way to reuse a style object — pass the variable directly to `sz`:

```tsx
const card = { p: 6, rounded: 'xl', shadow: 'md', bg: 'white' } as const;

// All three components share the same compiled className
<div sz={card} />
<article sz={card} />
<section sz={card} />
// → className="p-6 rounded-xl shadow-md bg-white"
```

`as const` is optional — the compiler resolves annotated and plain objects alike,
declared with either `const` or `let`.

:::tip[Sharing across files]
The examples above declare the object in the file that uses it. Move it to its
own module and a named import — relative or through a project alias — still
compiles exactly like the local declaration, because
[`build.importedStaticSz`](/docs/reference/config/#imported-static-sz-objects-importedstaticsz)
is on by default.

A namespace import (`import * as S`) and a default export written as a literal
compile the same way. What does not is a **barrel** — a module re-exporting a
name it does not declare — or a value that is not a plain object literal. Those
fall back to the runtime and contribute no classes, so the CSS goes missing, and
the build reports each one by name. [Across files](#across-files) has the
measured table.
:::

:::caution[A shared style object is a build-time value]
The compiler reads the object where it is **declared**, so that is the value it
compiles. Change the object afterwards and the class no longer describes it:

```tsx
// ❌ reassigned — csszyx stops resolving it and reports the fallback
let card = { p: 6 };
card = { p: 10 };
<div sz={card} />        // compiles to _sz(card) at runtime

// ❌ mutated — the compiler cannot see this, and compiles p-6
const card = { p: 6 };
card.p = 10;
<div sz={card} />        // renders p-6, not p-10
```

A reassignment is caught and falls back to the runtime, which is safe but costs
the build-time resolution. A **property write is not caught** — proving one never
happens would need whole-program analysis csszyx does not do. Treat a shared sz
object as declared once and never written to; build the variations with
[spread overrides](#override-with-spread) or [`szv()`](/docs/szv) instead.
:::

## Override with Spread

Use `sz={{ ...var, key: val }}` when some components need different values. **Last key
wins**, so you can layer overrides cleanly:

```tsx
const item = { p: 3, rounded: 'md', bg: 'white', border: true, borderColor: 'gray-200' } as const;

// Each variant adds or overrides specific keys
<div sz={item} />                          // base — p-3
<div sz={{ ...item, p: 6 }} />             // larger padding
<div sz={{ ...item, bg: 'blue-50', borderColor: 'blue-200' }} />  // tinted
```

:::tip[When to use which]
- **`sz={var}`** — no overrides needed. Simpler and equally efficient.
- **`sz={{ ...var, ... }}`** — only when you need to override or add properties.
:::

## Array Composition

Pass an array to compose multiple objects. The compiler merges fully-static arrays at
build time; conditional elements use `_szMerge` at runtime:

```tsx
const layout = { display: 'flex', items: 'center', gap: 3 } as const;
const text   = { text: 'sm', weight: 'medium' } as const;

// Static — single className string, zero runtime
<div sz={[layout, text]} />

// Conditional — only isActive element is dynamic
<div sz={[layout, text, isActive && { bg: 'blue-50' }]} />
```

Variables work as array elements too — no inline objects required:

```tsx
const active   = { bg: 'blue-500', color: 'white' } as const;
const disabled = { opacity: 50, cursor: 'not-allowed' } as const;

<button sz={[layout, isActive && active, isDisabled && disabled]} />
```

## Ternary Branches

When a component switches entirely between two styles, use a ternary:

```tsx
const active   = { bg: 'blue-500', color: 'white', shadow: 'md' } as const;
const inactive = { bg: 'gray-100', color: 'gray-600' } as const;

<button sz={isActive ? active : inactive} />
// Compiler emits: className={isActive ? "bg-blue-500 text-white shadow-md" : "bg-gray-100 text-gray-600"}
```

Both branches are compiled to static strings — no runtime object merging.

## Chained Variables

A variable can reference another variable in its initializer. The compiler resolves the
chain recursively:

```tsx
const base     = { p: 4, rounded: 'lg' };
const elevated = { ...base, shadow: 'md', bg: 'white' };
const featured = { ...elevated, ring: 2, ringColor: 'blue-500' };

<div sz={featured} />
// → className="p-4 rounded-lg shadow-md bg-white ring-2 ring-blue-500"
```

## Graceful Fallback

The compiler only resolves variables **declared in the same file** with a static object
literal initializer. Anything else falls back to the `_sz()` runtime helper — no crash,
no `[object Object]`:

| Pattern | Resolution |
|---|---|
| `const x = { ... }` (same file) | Build time ✅ |
| `const x = { ... } as const` | Build time ✅ |
| `const x = { ...other, key: val }` | Build time ✅ (recursive) |
| `sz={{ ...(cond ? a : b), key: val }}` | Build time ✅ (conditional spread hoist) |
| `const x = cond ? a : b` | Build time ✅ (both branches, wherever it is written) |
| `const x = cond && a` | Build time ✅ (the else arm is the empty style) |
| `import { x } from './styles'` | Build time ✅ (see [Across files](#across-files)) |
| `const x = getStyles()` | Runtime fallback |
| `const x = cond \|\| a` | Runtime fallback (`\|\|` keeps its left operand, which may itself be a style) |

In development, the compiler emits a build-time warning for any pattern it
falls back to `_sz()` — explaining why the fallback occurred and pointing to
the right alternative (`szv()` for static variants, `dynamic()` for runtime
data). The warning appears in the Vite/webpack dev-server output, not at runtime.

### Across files

An import is resolved when the compiler can follow the name to a **literal
object in the module that declares it**. What decides is that last hop, not the
import syntax — so the shape of the *export* is what to look at when a style
does not fold.

| Provider module | Importer | Resolution |
|---|---|---|
| `export const x = { ... }` | `import { x } from './styles'` | Build time ✅ |
| `const x = { ... }` + `export { x }` | `import { x } from './styles'` | Build time ✅ |
| `export const x = { ... }` | `import * as S from './styles'`, `sz={S.x}` | Build time ✅ |
| `export default { ... }` | `import x from './styles'` | Build time ✅ |
| `const x = { ... }` + `export default x` | `import x from './styles'` | Runtime fallback |
| `export { x } from './base'` (barrel) | `import { x } from './styles'` | Runtime fallback |
| `import { x } from './base'` + `export { x }` | `import { x } from './styles'` | Runtime fallback |
| `export const x = getStyles()` | `import { x } from './styles'` | Runtime fallback |

The three that fall back share one cause: the module the importer names does not
itself declare the value. A barrel forwards to a module the compiler has not
read, and `export default x` puts an identifier in the default slot rather than a
literal. A runtime fallback here is **missing output** — the classes were never
collected anywhere, so the CSS does not exist. The build reports it by name.

Reading imported objects is [`build.importedStaticSz`](/docs/reference/config/#imported-static-sz-objects-importedstaticsz),
which is on by default; turning it off makes every row above a runtime fallback.

## Component Variant Libraries

For predefined variant systems (intent, size, state…), use
[`szv()`](/docs/szv) instead of manual conditionals:

```tsx
import { szv } from 'csszyx';

const btn = szv({
    base: { px: 4, py: 2, rounded: 'md', weight: 'medium' },
    variants: {
        intent: {
            primary: { bg: 'blue-600', color: 'white' },
            ghost:   { bg: 'transparent', color: 'blue-600' },
        },
        size: {
            sm: { text: 'sm', px: 3, py: 1.5 },
            lg: { text: 'lg', px: 6, py: 3 },
        },
    },
    defaultVariants: { intent: 'primary', size: 'sm' },
});

<button sz={btn({ intent: 'ghost', size: 'lg' })} />
```

`szv()` handles the conditional logic and TypeScript inference — you define styles once,
use them everywhere.
